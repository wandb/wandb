# Unreleased changes

Add here any changes made in a PR that are relevant to end users. Allowed
sections:

- Added - for new features.
- Changed - for changes in existing functionality.
- Deprecated - for soon-to-be removed features.
- Removed - for now removed features.
- Fixed - for any bug fixes.
- Security - in case of vulnerabilities.

Section headings should be at level 3 (e.g. `### Added`).

## Unreleased

### Fixed

- `wandb leet symon` scaled the GPU PCIe and NVLink throughput charts and the Trainium memory charts by 1024³ on top of the bytes that the monitor reports, so their y-axis labels read like `7.67e+09GB/s` instead of `7.67GB/s` (@dmitryduev in https://github.com/wandb/wandb/pull/13191)
- The CatBoost `WandbCallback` logs every evaluation, including the last one, at the iteration CatBoost makes it. With `metric_period > 1` it used to log each value one evaluation late and drop the final ones (@David-Wu1119 in https://github.com/wandb/wandb/pull/13155)
- Offline runs once again display warnings generated by `wandb-core`, including when `run.log()` data is ignored because its step is lower than the current step (@willtryagain in https://github.com/wandb/wandb/pull/13037)
  - Regression introduced in 0.27.0
- `wandb.tensorflow.WandbHook` works again with TensorFlow 2.16 and newer (@dmitryduev in https://github.com/wandb/wandb/pull/13139)
- `wandb.integration.ultralytics` imports again with `ultralytics` 8.3.200 and newer (@dmitryduev in https://github.com/wandb/wandb/pull/13139)
- `wandb.integration.huggingface.autolog()` no longer requires the `pytz` package (@dmitryduev in https://github.com/wandb/wandb/pull/13139)
- Calling a pipeline that `wandb.integration.diffusers.autolog()` does not support no longer raises an error; the call is not logged (@dmitryduev in https://github.com/wandb/wandb/pull/13139)
- Importing `wandb.integration.lightning.fabric` or `wandb.integration.ultralytics` without the libraries they need now fails with an `ImportError` naming the missing package (@dmitryduev in https://github.com/wandb/wandb/pull/13139)
- Runs that finish right after they initialize, for example when `wandb sync` uploads a short run, no longer risk exiting before their final data and exit status are uploaded (@dmitryduev in https://github.com/wandb/wandb/pull/13153)
- Resumed runs no longer report a huge or negative `_runtime` and run duration, a regression in v0.30.0 (@dmitryduev in https://github.com/wandb/wandb/pull/12999)
- `wandb leet inspect` no longer prints "skipped corrupt data" forever when its output is piped and the file is not a `.wandb` log it can read; it now exits with an error (@dmitryduev in https://github.com/wandb/wandb/pull/12950)
- In W&B LEET TUI, the system metrics filter now applies to whichever run is highlighted, not only the run it was typed on. `Space` and `Enter` work in the runs list right after you filter runs with `f` from another pane (@dmitryduev in https://github.com/wandb/wandb/pull/12533)
- Changing system metrics grid rows or columns in LEET, including `wandb leet symon`, no longer crashes and takes effect immediately without waiting for new data (@dmitryduev in https://github.com/wandb/wandb/pull/12763)
- `wandb beta sync` no longer overwrites the earlier history of a resumed run when the backend reports a stale step. The starting step is now reconciled against the summary `_step`, the history tail `_step`, and the history row count (@geoffhardy in https://github.com/wandb/wandb/pull/12668)
- Calling `wandb.init()` after `wandb.agent(sweep_id, function=...)` returns now creates a new run instead of reusing and overwriting the last sweep run (@nathancy-wandb in https://github.com/wandb/wandb/pull/12970)
- Fixed a memory leak where every `wandb.Api()` object permanently retained a few MiB in the background service process after it was garbage collected (@dmitryduev in https://github.com/wandb/wandb/pull/12920)
- `Run.scan_history(keys=...)` no longer fails with `403 Forbidden` on W&B deployments that store run history in Amazon S3 (@dmitryduev in https://github.com/wandb/wandb/pull/12930)
- Per-process GPU metrics (`gpu.process.*`) are logged again for NVIDIA GPUs used by the process that called `wandb.init()`. Since v0.18.2, they were logged only when a subprocess used the GPU (@dmitryduev in https://github.com/wandb/wandb/pull/12978)
- NVIDIA PCIe and NVLink throughput system metrics from GPM (`gpu.N.pcieTxBytes`, `gpu.N.pcieRxBytes`, `gpu.N.nvlinkTxBytes`, `gpu.N.nvlinkRxBytes`) are now reported in bytes per second as their names say. They were in mebibytes per second (@dmitryduev in https://github.com/wandb/wandb/pull/12988)
- `network.sent` and `network.recv` system metrics no longer count loopback traffic, or count traffic twice through bonded and bridged interfaces (@dmitryduev in https://github.com/wandb/wandb/pull/13000)
- The Docker image ID recorded for runs inside Kubernetes no longer loses the start of the image name and the end of the digest when the `docker-pullable://` prefix is removed (@David-Wu1119 in https://github.com/wandb/wandb/pull/13035)
- `wandb.Api(overrides={"base_url": ...})` no longer changes the W&B server URL used by `wandb.init()` and other W&B calls later in the same process (@dmitryduev in https://github.com/wandb/wandb/pull/13125)
- Passing a run's `config` to `wandb.init(config=...)` or `run.config.update()` now copies its keys. Previously each pass nested the config one level deeper under an `_items` key. Passing `wandb.config` before `wandb.init()` adds no keys (@asg0451 in https://github.com/wandb/wandb/pull/13134)
- `wandb verify` no longer hangs on its final sweep check against W&B Server instances that deduplicate sweep run configs (Dedicated Cloud and Self-Managed 0.8x with sweep dedup enabled) (@rsong9527 in https://github.com/wandb/wandb/pull/13136)
- The `x_stats_gpu_device_ids` setting now limits which GPUs are reported for every vendor, including AMD and Apple GPUs, as documented. It applied only to NVIDIA GPUs (@dmitryduev in https://github.com/wandb/wandb/pull/13079)
- NVIDIA GPM system metrics such as `gpu.N.smActive` are now averaged over each run's own sampling interval. When several runs shared one process, each run's value covered only the time since any run's previous sample, and the cost of sampling system metrics grew with the number of runs (@dmitryduev in https://github.com/wandb/wandb/pull/13080)
- GPU, TPU and Apple accelerator system metrics resume when the helper process that collects them exits or fails to start; they used to stop for the rest of the run (@dmitryduev in https://github.com/wandb/wandb/pull/13098)
- `linked_at` is now accepted as a filter field in `api.registries().collections().versions(filter={"linked_at": ...})`, matching the existing `linked_at` order field (@ibindlish in https://github.com/wandb/wandb/pull/13161)
- Run metadata on AWS Trainium records the Neuron device and NeuronCore counts; they were always 0 (@dmitryduev in https://github.com/wandb/wandb/pull/13156)
- `wandb.plot.roc_curve` and `wandb.plot.pr_curve` (and the `wandb.sklearn` plots that use them) no longer score a class with another class's column of `y_probas` when `y_true` is missing some classes (@David-Wu1119 in https://github.com/wandb/wandb/pull/13097)
